POST_CAN_CHANGES.txt
====================
Date: 2026-04-12

Summary of all changes made to integrate CAN-over-TCP into ReceiveTest
and wire decoded data to the LVGL display.

=== PHASE 1: CAN receive pipeline ===

---- network/include/network.h ----
- Added #include <stdint.h>
- Changed data callback signature from (const char *data, int length)
  to (const uint8_t *data, int length) to correctly handle binary frames.

---- network/network.c ----
- Removed dependency on network_utils.h / network_sanitize_payload().
  The sanitizer stripped bytes < 32 or > 126, destroying binary CAN payloads.
- Replaced fixed RX_BUFFER_SIZE with CAN_FRAME_SIZE (13) and ACCUM_SIZE (13*8).
- Rewrote tcp_server_task() with a stream accumulator:
    * recv() output appended to a local buffer each call.
    * Dispatcher checks the first byte of the accumulator front:
        - First byte >= 0x20  => text command; consume up to null terminator.
        - First byte == 0x00  => binary CAN frame; consume exactly 13 bytes.
    * Handles recv() returning partial or multiple frames per call.

---- main/main.c ----
- Added #include <stdint.h> and #include "display_can_spec.h".
- Replaced s_last_data (char[128]) with s_can_data (display_data_t),
  zero-init in app_main() via memset.
- Rewrote on_data_received() for two paths:
    * Text path (data[0] >= 0x20): handles __CAM_START__ / __CAM_STOP__.
    * Binary CAN path (13 bytes): unpacks TCP envelope (4B CAN ID LE +
      1B DLC + 8B payload), calls display_route_frame(&s_can_data, id, payload),
      then calls ui_update_can_data(&s_can_data) if camera is not running,
      then clears s_can_data.update_flags.
- on_client_disconnected() resets display to "Waiting..." directly.

=== PHASE 2: Dashboard UI ===

---- components/can_spec/ (new component) ----
- Header-only component wrapping display_can_spec.h (as received from higher-up).
- Placed in components/ so both ui and main can depend on it without
  circular include paths.

---- components/ui/CMakeLists.txt ----
- Added can_spec to REQUIRES.

---- main/CMakeLists.txt ----
- Added can_spec to REQUIRES.
- Removed INCLUDE_DIRS "." (no longer needed; display_can_spec.h now
  lives in the can_spec component).

---- components/ui/include/ui.h ----
- Added #include "display_can_spec.h"
- Added: void ui_update_can_data(const display_data_t *data)
- ui_set_text() repurposed: writes to the status bar (was main data label).

---- components/ui/ui.c (full rewrite) ----
Replaced single text label with a full telemetry dashboard (1280x800):

  Top section (440px tall):
    Left panel  (260px): drive mode (PARK/FWD/REV) + regen ON/OFF indicator
    Center panel (760px): large speed readout in km/h
    Right panel  (260px): vertical SOC bar + SOC %, pack voltage, pack current

  Bottom tiles (288px tall, 4 equal columns):
    Tile 0: Motor temperature (°C), color-coded yellow/red at thresholds
    Tile 1: Controller temperature (°C), same thresholds
    Tile 2: Cell voltage spread (mV), yellow >20mV, red >50mV
    Tile 3: Total solar input power (W, sum of 4 MPPTs)

  Status bar (70px): IP address / connection messages

  Fault overlay (full screen minus status bar, hidden by default):
    Appears when BPS safety_state != SAFETY_NORMAL.
    Shows BPS_FAULT_NAMES string and limp-home grace timer countdown.
    Disappears automatically when fault clears.

  ui_update_can_data() checks update_flags before touching each widget,
  so only changed data causes LVGL label updates.

=== FUTURE WORK: Pit Telemetry System ===

The driver display only decodes a subset of the full CAN database.
A separate pit telemetry system is planned that must handle ALL messages
on the bus, including those not needed by the display:

  Messages NOT currently decoded (present in Simplified_CAN_Database_for_TELE):
    - MPPT1-4_Status       (mode, fault, enabled, ambient/heatsink temps)
    - MPPT1-4_Sweep        (IV curve sweep data)
    - MPPT1-4_SetMode/SweepCmd/SetVLim/SetILim  (command messages)
    - Vega_SafetyState     (packed Vega state byte, throttle out, LH timer)
    - Vega_ThrottleCMD     (throttle, CAN enable, direction, brake AD)
    - Vega_Fault           (Vega fault code + safety command)
    - BPS_FaultDetail      (full fault code, time-since-on, rolling counter)
    - BPS_SupplBatt_V      (supplemental battery — separate from BPS_SupplBattery)
    - BPS_DCDC_Stat_V      (DCDC in/out voltage and current)
    - BPS_Emergency        (shutdown reason, safety command, flags)
    - R_BMS_Fault          (DTC1/DTC2/Failsafe bitfields, severity)
    - R_BMS_Energy         (pack Ah, capacity, DOD, resistance)
    - R_BMS_AdaptEnergy    (adaptive SOC, Ah, capacity)
    - R_BMS_CellOpenV      (per-cell open circuit voltages)
    - R_BMS_CellResist     (per-cell resistance)

  Also note: BPS fault codes 14 (BMS_Shutdown) and 15 (VCU_MIA) exist in
  the database but are not named in display_can_spec.h's enum (which only
  goes to 13). The display shows "UNKNOWN FAULT" for these. The pit system
  decoder should include all 16 fault codes.

=== KNOWN ISSUE: Fault grace timer appears slow in broadcaster.py ===

  broadcaster.py scenario 4 ("FAULT - Precharge") sets grace_timer = 90s but
  SCENARIO_DURATION_S = 30s. The scenario switches away after 30 seconds, so
  the countdown only progresses from 90 down to ~60 before moving on — it
  appears to barely move. No code change made; left as-is for now.

  To fix when ready, either:
    (a) Lower grace_timer in scenario 4 to <= 25 (fits within the 30s window), or
    (b) Raise SCENARIO_DURATION_S to >= 95 so the scenario runs to completion.

  For the pit system, the CAN-over-TCP framing protocol is:
    [0x01 magic byte][CAN_ID 4B little-endian][DLC 1B][payload 8B] = 14 bytes
  This is the same protocol as the display; Vega forwards all bus traffic.
